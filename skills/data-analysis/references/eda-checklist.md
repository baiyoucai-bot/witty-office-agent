# 核查表

按需勾。不是每个任务都要走完 —— 只勾会改变结论的项，勾不动的写明为什么跳过。

跑 `scripts/profile_table.py` 能自动覆盖第 1–6 节的大部分，剩下的要人看。

## 1. 载入与结构

- [ ] 文件读进来没报错；编码、分隔符、引号异常已记录
- [ ] 行数在预期量级（差一个数量级就是读错了或筛错了）
- [ ] 列数和表头与说明一致；没有 `Unnamed: 0`、没有重名列
- [ ] **一行代表什么**已经写出来了（一个用户？一次工单？一个台区一天？）
- [ ] 主键找到了，并且验证过唯一
- [ ] 每列类型正确：日期是日期，编号是字符串（不是被当成数字丢了前导 0）
- [ ] 多表连接后行数变化能解释

## 2. 完整性

- [ ] 每列空值数和占比都看过
- [ ] 超过阈值的列已标记（见 `thresholds.md`）
- [ ] 分清了 `0` 和空值：这一列的 0 是真值还是「没填」
- [ ] 选填列的预期空值率写明了
- [ ] 空值的处理方式（保留 / 排除 / 填补）已选定并写进交付物

## 3. 唯一性

- [ ] 整行重复查过
- [ ] 主键级重复查过
- [ ] 部分重复（同 ID 不同时间）确认是版本化还是脏数据
- [ ] 是版本化的，取哪一条已经写明（最新？首次？）

## 4. 有效性

- [ ] 数值列在业务范围内（金额非负、比例 0–1、年龄合理）
- [ ] **单位一致**：没有混装元/万元、kWh/MWh、天/小时
- [ ] 分类列取值都在已知集合里；新增取值已问过
- [ ] 日期在合理区间，没有未来日期、没有 1900 这类哨兵值
- [ ] 外键连得上，孤儿记录数量已记录
- [ ] 布尔列不是 0/1/Y/N/是/否 混着放

## 5. 分布

- [ ] 数值列看过 mean / median / std / p5 / p95
- [ ] 偏度超线的列改用中位数和分位数
- [ ] 离群值逐个归类：真信号 / 数据错误 / 哨兵值
- [ ] 分类列没有某一类异常占到 90% 以上
- [ ] 日期分布连续，断档和尖峰能解释

## 6. 关系

- [ ] 数值列两两相关算过
- [ ] 强相关对（|r| ≥ 0.8）已标记并解释
- [ ] 本该相关的没相关 —— 查筛选条件和连接键
- [ ] 派生列和它的来源列对得上（金额 = 单价 × 数量）

## 7. 时间序列（涉及才勾）

- [ ] 时间列有序，缺口已记录
- [ ] 最新记录的滞后在预期内
- [ ] 分期计数没有异常断档或补数尖峰
- [ ] 周末、节假日、检修期的影响已考虑
- [ ] 同比、环比的两段口径一致

## 8. 业务对账

- [ ] 关键数字换一条路径复算过（分组求和对总量，或抽样手算）
- [ ] 分组小计能加回总计
- [ ] 与已有报表/系统的口径差异能解释（不是「差不多」）
- [ ] 已知的上游数据问题写进了交付物

## 9. 收口

- [ ] FAIL 项要么修了，要么明确写了「带风险继续」和风险是什么
- [ ] WARN 项写进交付物
- [ ] 排除了哪些行、为什么，写清楚了
- [ ] 结论没有超出数据能支撑的范围（见 `stats-guide.md`）
- [ ] 输出路径、格式、结构核对过
