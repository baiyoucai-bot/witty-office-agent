# NL2SQL 第 4 阶段：选一条并交付

**票数不等于正确。** 多个候选给出不同答案时，那是危险信号，不是投票现场。

输入：过了检查器的候选。输出：一条最终 SQL + 数据 + 图 + 按级别该有的分析。

## 1 按执行结果选，不按 SQL 文本选

```
sql_pick "<sql1>;;<sql2>;;<sql3>"
```

工具做的事：跑每个候选 → 按**结果集**聚类（结果相同的归一簇）→ `置信度 = 该簇候选数 / 候选总数`。

三条路：

| 情况 | 动作 |
|------|------|
| 单一结果簇、置信度达标 | 直接用。这是 DeepEye-SQL 的高置信捷径 |
| 多簇 | **不许按票数硬选**。逐簇比对，往下看 |
| 全部执行失败 | 别换写法硬试，回第 1 阶段重看 schema 和值采样 |

### 多簇怎么办

多簇说明至少有一种理解是错的。按这个顺序对：

1. **比行数**：行数差得多，先怀疑连接扇出或 INNER JOIN 丢实体。
2. **比粒度**：把每簇的「一行代表什么」说出来，和用户问的粒度对。
3. **比口径**：过滤条件、时间边界、排除规则，哪一簇和第 1 阶段定的口径一致。
4. **抽样复核**：对差异最大的那一簇，`sql_run` 一条只看几行明细的 SQL，人工核对几条记录。

定不下来就**把分歧摆给用户**：说清两种理解各自得到什么数、差在哪里，让用户定口径。**不要挑一个数交上去**。

单一候选（简单查询）直接 `sql_run`，但要在结论里说明没做交叉验证。

## 2 判分析深度

**照问题类型定，不是越多越好。** 判据和各级必须交付什么见 `nl2sql` 技能的 `references/analysis-depth.md`。

| 级 | 问题 | 图 | 分析 |
|----|------|-----|------|
| L0 | 查明细 | 不出 | 不做 |
| L1 | 单指标 | 不出 | 一句口径 |
| L2 | 对比/构成/排名 | 一张 | 差距点名（极差、倍数、头部占比） |
| L3 | 趋势/时序 | 折线 | 环比同比 + 波动是否超出常态 |
| L4 | 归因/异常/预测 | 多张 | 维度拆解到贡献度 + 区间 |

判不准往低一级走。**L0 出图是噪声，L3 不出图是偷工。**

## 3 出图

数据先落文件，再用沙箱解释器画——核心包不带 matplotlib，别在别处 import：

```bash
sql_export "<最终 SQL>" <工作目录>/result.csv
<沙箱 Python> <技能目录>/scripts/plot_result.py --input result.csv --chart line --out trend.png
```

图表类型按 `nl2sql` 技能的 `references/chart-decision.md` 选，**不要默认柱状图**。

长表（月份、区域、数值三列）画多序列要加 `--series <维度列>`。

脚本会拦五种情况：没有数值列、饼图类别超 6、折线的 X 轴不像时间、`table` 类型、折线序列超 5 条。**被拦了改图表类型或先聚合，不要加参数硬绕。**

脚本还会顺带打出要点数字（最高最低、极差、倍数、环比、首末变化、末值偏离几个 σ）——写分析时直接引用这些数，不要自己心算。

## 4 写结论

### 结构

1. **答案先给**：第一句就是用户问的那个数或那个结论。
2. **图**（L2 以上）。
3. **分析**：按级别该有的内容，不多不少。
4. **口径与出处**：算的是哪些行、排除了什么、口径来自 wiki 哪一页还是用户哪句话。
5. **SQL**：实际执行的那一条，原样贴。不贴就没法复核。

### 必须在开头就说的事

不要埋在末尾：

- 置信度不达标，或结果多簇
- 口径是靠假设补齐的（写明假设了什么）
- 数据不完整（时间有断档、某些实体没有记录）
- 做了截断（只画了前 N 项，被丢掉的是哪些）

### L4 的统计红线

守 `data-analysis` 已定的四条：

- **相关不写成因果**。数据里看到同步变化就写「同步变化」，不写「导致」。
- **点估计不算结论**，给区间。
- **显著不等于重要**，给效应量和业务含义。
- **变化先和自身波动比**，±1.5σ 内先当噪声。

数据支撑不到归因（只有一个维度、期数太少、没有对照）时**明说做不了**，降到 L3 交付。

## 5 收口检查

- [ ] 交付里有实际执行的 SQL
- [ ] 有行列数
- [ ] L2 以上有图，L0/L1 没有多余的图
- [ ] 每个数字都能在 SQL 结果里找到出处
- [ ] 口径和排除规则写了出处
- [ ] 置信度/假设/截断都在开头说了

## 常见坑

- **多簇按票数选**：三条候选里两条犯同一个连接扇出错误，票数反而是错的那边多。
- **图和文对不上**：正文说「江北新区最高」，图上最高的是市区——通常是画图时排序或截断改了顺序。
- **L4 拿相关性凑因果**：「负荷涨是因为气温高」——数据里只有两条同步上升的曲线，就只能这么写。
- **口径不写出处**：三个月后没人知道这个「有效台区」是怎么定的。
- **只贴结论不贴 SQL**：数字无法复核，等于让用户凭信任接受。
