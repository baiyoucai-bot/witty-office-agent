# NL2SQL 问数

问句进，**可执行 SQL + 数据 + 图 + 结论**出。四个阶段照 DeepEye-SQL 的软件工程骨架走，每阶段有收口条件，不许跳。

## 何时用

用户要的数在数据库里。要分析本地 CSV/Excel 走 `data-analysis`，只看表头空列走 `table_qa`，这里不碰文件。

## 硬规矩

1. **只读**。`sql_run` 只吃 SELECT/WITH，写类语句它会拒；不要绕。
2. **不猜 schema**。表名列名一律来自 `sql_schema`，猜一个就等于编数据。
3. **标识符原样抄**。库里写「江北新区」就不要写成「江北区」，不做简繁、大小写、空格转换。
4. **行数永远有上限**。用户说「全部数据」也一样，工具会强制加。
5. **数字必须有 SQL 出处**。交付里贴出实际执行的那条 SQL，不贴就是不可复核。

## 四阶段

### 1 意图落地

先定三件事，缺一件就问，不要带着歧义往下写 SQL：

- **口径**：「负荷」是瞬时值还是均值？「上半年」含不含 6 月？
- **粒度**：一行代表什么——一个站一天，还是一个站一个月？
- **范围**：哪些要排除（试运行站、作废单）？

多源时先 `sql_sources`。然后 `sql_tables <问句>` 收窄候选表，`sql_schema --tables a,b --samples 3` 看真实结构和取值。问句里的词对不上库里的写法时用 `sql_values` 采样对齐——这是把「江北」对到「江北新区」的唯一正当手段。

业务口径、指标定义、同义词查 `wiki_search`；查到的口径要在结论里说明出处。库里没有、wiki 里也没有的定义，问用户，不要自己发明。

细节见 `nl2sql-schema` 技能。

### 2 出候选

**先写查询计划，再写 SQL**（SQL-of-Thought）。计划用自然语言说清：取哪些表、怎么连、按什么分组、怎么过滤、怎么排序。计划里出现 SQL 关键字就是跑偏了。

计划定了再出 **2-3 个结构不同**的候选——不是同一条改改别名，是真的换写法（直接聚合 / 子查询 / CTE 分步）。结构相同的候选一起错，等于没验。

细节见 `nl2sql-sql` 技能。

### 3 过检查器

每个候选都过 `sql_check <sql> <schema> <source>`：

- **两个参数都要给全**：schema 带着可空标记和列类型，`source` 决定按哪个方言查时间函数。少给一个，空值段和时间段会直接沉默——那是没查，不是通过。
- 有 **FAIL** 就改，改完重新过，不要带着 FAIL 执行。
- 只有 **WARN** 可以执行，但每条 WARN 要么改掉、要么在结论里说明为什么可接受。
- 同一个 FAIL 改两轮还在，回第 1 阶段——通常是口径就理解错了，不是 SQL 写错了。

检查项和对应的典型错因见 `references/checkers.md`，错误分类法见 `references/error-taxonomy.md`。

### 3.5 0 行不是答案

`sql_run` 查到 0 行时会把 WHERE / HAVING / ON 条件逐条原样列出来。**逐条复查，别直接回「没有数据」**——值写法、时间区间右端点、JOIN 过滤、`NOT IN` 碰 NULL 这四种都会静默返回空表。定位办法只有一个：一次只去掉一条约束跑一遍。

同理，`sql_pick` 的最大簇是 0 行时不走高置信度快捷路径：几个写法一致地查空，通常是共用了同一个错约束。

### 4 选一个并交付

候选 ≥2 个时用 `sql_pick "<sql1>;;<sql2>"`：按**执行结果**聚类，不按 SQL 文本。

- 单一结果簇且置信度达标 → 用它。
- **多簇就是危险信号**：不同写法给出不同答案，至少一种理解是错的。逐簇比对语义，找出哪个粒度/连接错了，**不许按票数硬选**。
- 全部失败 → 别换写法硬试，回第 1 阶段。

细节见 `nl2sql-deliver` 技能。

## 分析做多深

**照问题类型定，不是越多越好。** 判据和各级必须交付什么见 `references/analysis-depth.md`：

| 级 | 问题 | 交付 |
|----|------|------|
| L0 | 查明细 | 只给表，不出图不分析 |
| L1 | 单指标 | 数字 + 一句口径 |
| L2 | 对比/构成/排名 | 图 + 差距点名 |
| L3 | 趋势/时序 | 折线 + 环比同比 + 波动是否异常 |
| L4 | 归因/异常/预测 | 多图 + 维度拆解 + 区间 |

L0 出图是噪声，L3 不出图是偷工。判不准就往低一级走，别硬凑分析。

## 出图

`sql_export <sql> <路径.csv>` 落数据，再用**沙箱解释器**出图：

```bash
<沙箱 Python> <技能目录>/scripts/plot_result.py --input <结果.csv> --chart line --out <图.png>
```

图表类型按 `references/chart-decision.md` 选，不要默认柱状图。核心包不带 matplotlib，别在别处 import。

## 收口

交付里必须有：实际执行的 SQL、行列数、图（L2 以上）、按级别该给的分析、口径与排除规则的出处。

置信度不达标、结果多簇、口径靠假设补齐的，**在结论开头就说**，不要埋在末尾。L4 的统计口径守 `data-analysis` 的四条红线：相关≠因果、点估计不算结论、显著≠重要、±1.5σ 内先当噪声。
