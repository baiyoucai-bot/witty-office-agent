# PPT Master

产出 **WPS / Office 里能改字、改表、换图** 的 `.pptx`。风格和版式按**这一次用户要求**现场发明，不要先从内置主题里挑一套。

HTML 预览是同稿副产物。不要整页截图、公网模板、任意网页硬转。

## 少问，直接干

用户已经点名动作时，**别再连环确认**：

| 用户说 | 你做 |
| --- | --- |
| 「重新生成一份 PPT」且工作区已有同主题稿 | 用最近一份 + 原主题（如 grid）直接重渲，不要问 A/B |
| 「把那个 Word 生成 PPT」且刚写过/打开过一份 docx | 就用那份；政企题材默认 `theme: "grid"`；可研默认**完整覆盖章节**（≥15 页），不要先问精简还是详细 |
| 「继续」「重新做」「让你干啥你就干啥」 | 停问，动手 |

缺主题/听众/页数会**改交付物性质**时才问一次。风格、页数能从文档结构推断就推断。

## 开始前

问清主题、听众、页数、风格（仅在上面表格兜不住时）。用户点名 **青绿 / 数字化审计 / 审计培训** 时，`theme` 用 `"grid"`（青绿 `#01706C` + 金线 `#FFC20A`），不要改成藏青或珊瑚。其它风格按口述发明 token。

## 青绿金线企业模板（theme=grid 时引擎自动出）

- **封面**：写 `kind: "cover"` 宏（title/subtitle/kicker/meta），引擎按模板排：通栏青绿带 + 带底金线；主题带徽标/标识时自动摆放。**不要用 boxes 自己仿封面**。示例见 `references/deck-schema.md`。
- **章节页**：写 `kind: "section"` 宏（kicker 放号数如 `01`），引擎排通栏青绿带 + 左侧浅色号数块。
- **内容页**：必须自己排版（`layout` 或 `boxes`）。引擎自动垫顶部白带压线、补页脚；主题带标识时右上角自动摆标识。内容从 **y ≥ 1.35** 起排——走 `layout` 就把根节点的上内边距设成 **1.35**（`"pad": [1.35, 0.62, 0.62, 0.62]`）。**右上角 x ≥ 11.0 且 y ≤ 1.1 是标识区，别放内容**（压了会被 lint 报 `logo_zone`）。
- 主题带标识时标识一定会出现；只有页里自己摆了 `name: "witty-logo"` 的盒子时引擎才让位。

## 排版用 layout，不要手算坐标

内容页写 `layout` 声明式排版：`{"dir":"row","gap":0.24,"children":[...]}`，宽高位置引擎算。横排里不给宽就是等分，文字高度按真实字宽量。四张卡就是把一个卡片节点重复四份改文案。

手填 `x`/`y`/`w`/`h` 的 `boxes` 只留给全幅底图和骑线压字。**别再为一排卡片手算坐标**——算术预算花在排版上，稿子就只能做得又空又稀。

`layout` 页也必须有标题级文字：根上放 `name: "witty-title"` 的 text 节点，或页级 `title` 字段（chrome=band 时引擎画抬头）。缺了会报 `no_title`。不要因为一次 `no_title` 就整稿退回手算 boxes。

细则和例子看 `references/deck-schema.md`。

## Word / 可研 → PPT

把长文做成汇报稿时走这条，**禁止边追加边替换导致页码漂移、重复页**：

1. 抽正文与表格数字（docx 段落 + 表格对象），数字只认文档，不编。
2. 先写**完整大纲**（封面 / 目录 / 每章 section + 内容页），页数一次定死。
3. 用 Python 字典 `json.dump` 生成整份 `deck.json`（不要手拼带转义的 JSON 字符串）。
4. **优先一次 `pptx_render` 整稿写出**。超过 8 页才分块：第一批 render，之后每批 5–8 页 `pptx_add_pages`；每批 JSON 必须自带 `witty-kicker` + `witty-title`。
5. 中途发现顺序错了 / 重复了：**停追加**。`pptx_outline` 核对 → 拼回完整 deck → **整份重渲一次**。不要在错误页码上继续 `replace_slide` + `add_pages`。
6. 交稿前 `pptx_check`；只修 FAIL / overlap / contrast / footer_band / edge / tiny_text。**单为 `slack` 不要反复挪坐标**——挪完常引出 overlap。

## 配色红线（grid 尤其）

深底浅字、浅底深字。彩色底上的字必须过对比度（lint `contrast` ≥ 约 3:1）：

| 可用 | 勿用 |
| --- | --- |
| 深青 `#01706C` / `#123F3C` + 白字 | `#2FA98B`、`#3C9B91` 等浅青绿 + 白字（对比约 2.9） |
| 深橙 `#9A4A00` / `#BF6A0A` + 白字 | `#E67E22` + 白字或浅米黄字 |
| 浅卡 `#EAF7F3` / 白底 + 深墨 `#1F3A36` | 任意浅色扇区默认指望白字标签 |

饼/环图扇区用偏深色；引擎标签已是深墨 14pt 且显示数值+百分比，浅黄扇区也能读。**不要解压 pptx 手改 chart XML**。

## 关系用图画，不要写成第二串要点

有先后、有层级、有分支的内容，画成图比列要点强。矢量形状 `chevron` `pentagon` `arrow` `oval` `diamond` `triangle` 落的是 PowerPoint 原生形状，客户在 WPS 里还能改。

- **流程 / 步骤**：一行 `chevron`，中间夹 `arrow`。别写成「第一步…第二步…」的要点。
- **架构 / 分层**：每层一行，层名一个实心 `rect`，右边几个 `stroke` 空心框。纵跨别压页脚（内容下沿 ≤ **6.80**）。
- **时间轴**：一条 `line` 打底，上面排 `oval` 节点。
- **判定分支**：`diamond` 加带箭头的 `line`（`line` 给 `point` 就是连接线）。

形状的 `text` 写在形状**里面**，不要另摞文本框。一页里流程图或架构图能顶掉一整屏要点，密度和观感都比列表好。

## 美观（必须）

- 页边 **0.62–0.70 英寸**。标题区到内容 **≥ 0.28**。卡片间距 **0.24**。
- 字号：kicker **11–12** 强调色加粗；标题 **28–34** 加粗；正文 **15–17**；页脚 10。**正文不要低于 12**（`tiny_text`）。
- 卡片用 `round`（引擎会加浅影）。左侧可加 0.05 宽的 accent 竖条。
- 深底用浅字，浅底用深字。强调色只做点缀，不要大面积铺。
- 封面留白：标题不要顶天，副题与标题之间留一条 1.4×0.05 的 accent 线。

## 密度是下限，不是上限

一页一个观点指的是**一个论点**，不是「一页只放三句话」。空稿子不是克制，是没干活。内容页按这个排：

| 页型 | 至少要有 | 正文字数下限 | 主视觉占内容区 |
| --- | --- | --- | --- |
| 单主题内容页 | 标题 + 正文 + 主视觉 | 180 | ≥ 30% |
| 卡片组 | 标题 + 引导句 + N 张卡 | 每卡 ≥ 60 | — |
| 数据页 | 标题 + 数字组 + 一条判断 | 80 | ≥ 50% |
| 章节页 | 章节号 + 标题 + 副标 | 30 | ≥ 40% |

- 每张卡除了标题还要有一句说明，别只放光秃秃的名词。
- 数据页给了数字就要给**判断**——「83%」下面必须跟着这个数意味着什么。
- 卡片内容垂直占用 **≥ 85%**；占不到就补内容或压低卡片高度，`pptx_check` 会按 `slack` 报出来。
- 卡片张数跟着内容走，4 张一排是常态；`layout` 等分不用你算宽度。

## 生产路径

1. `theme`：青绿金线企业风写 `"grid"`；其它场合写成对象（`bg` `ink` `muted` `accent` `accent2` `cover_bg` `cover_ink` `font`，颜色 `#RRGGBB`）。
2. 画布 16:9 = **13.333 × 7.5 英寸**。内容页必须自己排版：优先写 `layout`，全幅底图那类写 `boxes`。盒子 `kind`：`rect` `round` `text` `bullets` `table` `image` `line` `chart` `oval` `diamond` `triangle` `chevron` `pentagon` `arrow`。标题 `name=witty-title`，正文 `witty-body`，kicker `witty-kicker`。
3. `pptx_render` 写出 `.pptx` + 同名 `.html`。改口就改 JSON 再渲。落盘是原子换名，文件要么是上一版要么是新版，不会写出半截稿。
4. 交稿前 `pptx_check`。有溢出/叠字/对比问题必须改。`slack` 单独出现可以补一句说明后交，不要为修 slack 把布局拆坏。
5. 交稿前再 `pptx_snapshot` 画一张 PNG 联络表，**用读图工具打开亲眼看**：色带在不在、标识丢没丢、排布歪没歪。看完再交。

## 字体

`theme.font` 只用域内放映机必装的字体：微软雅黑 / 宋体 / 黑体 / 等线 / 仿宋 / 楷体 / Arial / Calibri / Times New Roman。清单在 `config/runtime.toml` 的 `[pptx].safe_fonts`，用清单外的字体 `pptx_check` 会报 `font_risk`——放映机没装那台就整稿跑版。生成机上缺字体不算错（换行按真实字宽量不到就回落估算），放映机缺才是事故。

## 自查快照（pptx_snapshot）

`pptx_snapshot(deck_path="稿.html")` 在旁边落一张 PNG 联络表，纯本地光栅，不开浏览器、不装 LibreOffice。几何、配色、白带/压线/标识/色带跟成稿同源，坐标一致；**文字是本机字体重画的近似**，字距行位跟 PowerPoint 会有漂移，别拿它当成稿验收字。它管的是「模板画坏没有」，不是「字挤没挤」——字的事交给 `pptx_check`。

## 长稿分块（页数 > 8 必须走）

用户要多少页就出多少页，**不许因为页数多而减页或糊弄**。一次塞几十页 JSON 只会降质，按批出：

1. 第一批 `pptx_render`：封面 + 章节页 + 前 3–5 页内容。
2. 之后每批 **5–8 页** `pptx_add_pages`（页码、页脚、主题自动接上，预览同步追加）。每批都把该批内容排满排好，质量与第一批一致。**不要一次只塞 2–3 页**。
3. 单次 `pptx_render` 上限 40 页，超过必然截断——超长稿只能走分块。
4. 收尾 `pptx_check`（`deck_path` 指向最终 `.html`）做全稿检查，有问题回去改对应页。注意：`pptx_replace_slide` **不会刷新 html**，全稿检查前若改过单页，应用完整 deck 再 `pptx_render` 一次，或对 pptx 做 outline 核对，别只信过期 html。

**断了怎么续**：不要重头重渲，也不要凭记忆猜写到第几页。`pptx_outline("稿.pptx")` 读回真实页码和每页文字，认准最后落盘的那页，从下一页接着 `pptx_add_pages`。写盘是原子的，断点处的文件是完整的上一批结果，不会是半截。

## 改已有稿

| 你要改什么 | 用什么 |
| --- | --- |
| 某一块文案/颜色/字号 | `pptx_list_boxes` 找到 `name`，再 `pptx_edit_box` |
| 整页重排 | `pptx_replace_slide`（该页 boxes JSON） |
| 加一页 | `pptx_add_page`（`index` 为 0 追加，>0 插入） |
| 批量续页 | `pptx_add_pages`（一批 5–8 页） |
| 只改标题要点（旧稿） | `pptx_edit_slide` |

不要为改一个标题整份重渲。结构级错误（重复页、缺章）整份重渲比连环 replace 便宜。

## 纪律

- 数字必须来自用户或本地文件。
- 表格用 `table`，图表用 `chart`。配图只用本地路径。
- 内容页禁止用 `kind: bullets` 等宏交正式稿；封面/章节页的 `cover` / `section` 宏是模板，正式稿可用。
