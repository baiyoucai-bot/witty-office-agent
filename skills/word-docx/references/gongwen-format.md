# 公文格式判定线

GB/T 9704-2012《党政机关公文格式》。这份表是 `scripts/gongwen.py` 的取值来源，也是 `scripts/check_docx.py` 的判定线。改任何一个数都要同时改脚本，不要只改表。

FAIL 是「不改就不是公文」，WARN 是「要说明为什么」。

## 版面（4.1）

| 项 | 标准值 | 判定 |
|----|--------|------|
| 纸张 | A4 210mm × 297mm | 差 > 0.5mm 判 FAIL |
| 天头（上白边） | 37mm ± 1mm | 超容差 FAIL |
| 订口（左白边） | 28mm ± 1mm | 超容差 FAIL |
| 版心 | 156mm × 225mm | 差 > 2mm FAIL |
| 每面行数 | 22 行 | 少一行 FAIL |
| 每行字数 | 28 字 | 少一字 FAIL |

切口（右）和地脚（下）标准正文里**没有直接给**，是减出来的：

```
切口 = 210 − 156 − 28 = 26mm
地脚 = 297 − 225 − 37 = 35mm
```

网上流传的模板常把右边距写成 28mm、下边距写成 37mm（跟左、上对称），那样版心就变成 154×223mm，每行少一个字。判版心宽高比判边距可靠。

## 两个错得最多的参数

这两个值网上的「标准参数」都给错了，而且错了不报错、打印出来也像对的。**实测**结论，不是推算：

| 参数 | 流传值 | 正确值 | 错了会怎样 |
|------|--------|--------|-----------|
| 固定行距 | 29pt | **28.95pt**（`w:line="579"`） | 每面只排 21 行 |
| 正文字距 | 不压 | **压 −0.25pt**（`w:spacing w:val="-5"`） | 每行只排 27 字 |

行距：版心高 225mm = 637.795pt，22 × 29 = 638pt，超 0.2pt。Word 把第 22 行挤到下一页。取 579 twips（28.95pt）时 22 行 = 636.9pt，装得下。

字距：版心宽 156mm = 442.20pt，28 个 3 号字 = 28 × 16 = 448pt，天生超 5.80pt，所以默认每行只排 27 个字。要压回来，每个字至少让 5.80 / 28 = 0.207pt，`w:spacing` 单位是 1/20 磅，取 −5（−0.25pt）。**−4 不够**（28 × 15.8 = 442.4pt，仍超 0.2pt），实测就是 27 字。

只设 `w:docGrid` 的 `charSpace` 不管用，实测 0 / −8 / −12 都是 27 字。压字距必须写在 run 的 `w:rPr/w:spacing` 上。

## 版头（7.2）

自版心左上角第一行往下排，缺哪项就不占行：

| 要素 | 位置 | 字体字号 |
|------|------|----------|
| 份号 | 顶格第 1 行，6 位阿拉伯数字 | 3 号仿宋 |
| 密级和保密期限 | 顶格第 2 行，如「秘密★1年」 | 3 号黑体 |
| 紧急程度 | 顶格密级下一行，如「特急」 | 3 号黑体 |
| 发文机关标志 | **上边缘距版心上边缘 35mm**，居中 | 2 号小标宋，红色 |
| 发文字号 | 发文机关标志下空二行，居中 | 3 号仿宋 |
| 签发人 | 只上行文有。发文字号改为左空一字，签发人右空一字同行 | 「签发人：」仿宋，姓名楷体 |
| 红色分隔线 | 发文字号**下 4mm**，与版心等宽 | 标准未规定线粗，取 1 磅 |

那 35mm 是从版心上边缘量的，不是从纸边。份号 / 密级 / 紧急程度占掉的行高要**减掉**，余量用段前距顶出来。用空行凑只能凑到行距的整数倍，有份号时会顶到 61mm 上下。

4mm 那个间距同理：放它的空段行高必须压到 1pt 左右，否则 4mm 被 28.95pt 的行高整个吃掉。

## 主体（7.3）

| 要素 | 位置 | 字体字号 |
|------|------|----------|
| 标题 | 红线下空二行，居中，回行不能把词拆开 | 2 号小标宋 |
| 主送机关 | 标题下空一行，居左顶格，末尾全角冒号 | 3 号仿宋 |
| 正文 | 主送机关下一行，**每自然段左空二字** | 3 号仿宋 |
| 附件说明 | 正文下空一行，左空二字「附件：」 | 3 号仿宋 |
| 发文机关署名 | 正文下空一行，右空二字 | 3 号仿宋 |
| 成文日期 | 署名下一行，**首字比署名首字右移二字** | 3 号仿宋，阿拉伯数字 |
| 附注 | 成文日期下一行，左空二字，加圆括号 | 3 号仿宋 |

三条容易漏的：

- **附件说明多于一件要加顺序号**，且回行与冒号后首字对齐（悬挂缩进 2 + 3 = 5 字）。
- **成文日期不能靠「右空 = 署名宽 − 日期宽」定位**。那个公式在字宽上是对的，但要把日期
  自己的宽度算进去，而「2026年8月20日」里的阿拉伯数字实测约 0.64 字宽、不是半角的 0.5，
  7 个数字差出 1 个字——日期只右移了 1 字。改成按左缩进定位：`左空 = 版心字数 − 署名宽`，
  只依赖纯汉字的署名，跟日期多宽无关。没有署名时才退回右空二字。
- 缩进的**入参**用字（「左空二字」），**写进 XML 的**是磅（`w:left` / `w:hanging`）。
  不要用 `w:leftChars` / `w:hangingChars` —— 实测悬挂方向是反的、字宽还按 `Normal` 样式
  的字号算，见 `docx-traps.md`「缩进：磅和「字」都会错」。

## 层次序数（7.3.3）

| 层 | 写法 | 字体 |
|----|------|------|
| 一 | 一、 | 3 号黑体 |
| 二 | （一） | 3 号楷体 |
| 三 | 1. | 3 号仿宋 |
| 四 | （1） | 3 号仿宋 |

第三、四层同为仿宋，不是「递进变细」。层一层二不加粗，是换字体，用 `bold=True` 冒充黑体属于 FAIL。

## 版记（7.4）

有抄送或印发机关才排，置于文末：

| 要素 | 位置 | 字体字号 |
|------|------|----------|
| 抄送机关 | 首条分隔线下，左右各空一字，「抄送：」回行对齐冒号后首字 | 4 号仿宋 |
| 印发机关 | 末行左空一字 | 4 号仿宋 |
| 印发日期 | 末行右空一字，同行 | 4 号仿宋 |
| 分隔线 | 三条，与版心等宽 | 首末 0.35mm，中间 0.25mm |

`w:pBdr/w:bottom` 的 `w:sz` 单位是 **1/8 磅**：0.35mm ≈ 1 磅 = 8，0.25mm ≈ 0.75 磅 = 6。所以三条线是 8 / 6 / 8。

## 页码（7.5）

| 项 | 标准 |
|----|------|
| 字体字号 | 4 号宋体，阿拉伯数字 |
| 形式 | 数字左右各一条一字线，如 — 5 — |
| 位置 | 上边缘距版心下边缘 7mm，即距纸张下边缘 35 − 7 = 28mm |
| 单双页 | 单页码居右空一字，双页码居左空一字 |

单双页分排要开 `settings.xml` 里的 `w:evenAndOddHeaders`，光设两个页脚不生效。页码必须是 `PAGE` 域，写死数字一改分页就全错。

## 字号磅值

| 字号 | 磅 | 用在 |
|------|-----|------|
| 2 号 | 22 | 标题、发文机关标志 |
| 3 号 | 16 | 正文及主体绝大多数要素 |
| 4 号 | 14 | 版记、页码 |

3 号 = 16pt 是这套版式的地基：22 行、28 字、字距 −5 全都是由它推出来的。改字号必须重算这三个数。

## 字体名

标准写「仿宋」「黑体」「楷体」「小标宋」，指的是字族，不是某个文件名。同一字族在不同系统里名字不一样：

| 字族 | 常见实际字体名 |
|------|---------------|
| 仿宋 | 仿宋、仿宋_GB2312、FangSong、STFangsong |
| 黑体 | 黑体、SimHei、STHeiti |
| 楷体 | 楷体、楷体_GB2312、KaiTi、STKaiti |
| 小标宋 | 方正小标宋简体、FZXiaoBiaoSong-B05S |

校验按字族判，不按字面判。目标机器上没装的字体会被静默替换，交付前在目标机器上看一眼实物。
