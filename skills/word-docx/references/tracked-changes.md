# 修订留痕

公文要走起草→审核→会签→签发。审核阶段改稿必须留痕，否则签发人看不出哪句是谁改的，
公文也进不了审核环节。这份是 `scripts/revise.py` 的依据和 `check_docx.py --mode revise`
的判定线。

下面的实测都在本机 pandoc 3.9.0.2 + libreoffice + 沙箱 Python 上做的，换版本自己再验。

## 结构

改一句话 = 删旧的 + 插新的，两个动作各自留痕：

```xml
<w:ins w:id="1" w:author="李审核" w:date="2026-08-20T21:00:00Z">
  <w:r><w:rPr>…</w:rPr><w:t xml:space="preserve">相关工作要求</w:t></w:r>
</w:ins>
<w:del w:id="2" w:author="李审核" w:date="2026-08-20T21:00:00Z">
  <w:r><w:rPr>…</w:rPr><w:delText xml:space="preserve">有关事项</w:delText></w:r>
</w:del>
```

四条硬要求，违反了都不报错：

| 要求 | 违反后果 |
|------|----------|
| `w:del` 里是 `w:delText`，不是 `w:t` | Word 当这段字还在，接受修订时删不掉 |
| `w:id` 全篇唯一 | 逐条接受/拒绝时可能连带处理别的 |
| `w:author` / `w:date` 都要有 | 审阅窗格里分不出是谁改的 |
| `w:date` 是 ISO 8601 带 Z | 显示成「未知时间」 |

## 段落标记就是「并入下一段」

`w:pPr/w:rPr/w:del` 标的是**段落标记**本身，语义是「本段并入下一段」。所以：

```
整段删除 = 段内每个 run 包 w:del  +  段落标记也标删
```

只包 run 不标段落标记，接受修订后会**剩一个空段**。公文里那就是版心中间多一个空行；
自动编号列表里那就是一个空项。`check_docx.py --mode revise` 的 WARN 查的就是这个。

`w:del` / `w:ins` 必须是 `w:rPr` 的**第一个**子元素，schema 里这个顺序是强制的。
排到 `w:rFonts` 后面 Word 可能把整个 `rPr` 当无效。

## 接受和拒绝

| 留痕 | 接受 | 拒绝 |
|------|------|------|
| `w:ins` 包着的 run | 拆掉外壳，内容留下 | 整块删掉 |
| `w:del` 包着的 run | 整块删掉 | 拆掉外壳，`w:delText` 改回 `w:t` |
| 段落标记 `w:del` | 并入下一段（本段消失） | 只去掉标记，段落留着 |
| 段落标记 `w:ins` | 只去掉标记 | 并入下一段 |
| `w:pPrChange` / `w:rPrChange` | 扔掉记录 | 用记录里的旧属性还原 |

并段时**后一段的段落属性留着**——Word 就是这样，存活的是后一个段落标记。

自查用得上的一条：**全部拒绝，应当逐字回到原稿。**回不去就是有改动没留痕。
`check_docx.py --original` 就是拿这个当判据，比按作者名查硬——作者名只能证明
「这个人的改动包了 `w:ins`」，证明不了「没人绕过留痕直接改字」。

## 实测：pandoc 不能用来接受修订

`pandoc --track-changes=accept` 是「解析成 AST 再重新生成」，不是在 XML 上做手术。
一份 29 段的公文过一遍：

| | 段数 | 起间隔作用的空段 | sectPr（纸张/版心/网格） | 压字距的 run | `w:eastAsia` |
|--|-----|----------------|------------------------|-------------|-------------|
| 原公文 | 29 | 9 | 有 | 11 | 25 |
| pandoc 过一遍 | 20 | **0** | **整个丢失** | **0** | **0** |

版式全毁：纸张回默认、每面行数每行字数全变、中文字体退回宋体。文字看着还在，
所以很容易以为成功了。**接受修订必须在 XML 上做，用 `revise.py --accept`。**

顺带一条版本差异，记下来免得下次照抄结论：Anthropic 那份 docx 技能写
「`pandoc --track-changes=accept` 从不并段，会留下空段」。本机 3.9.0.2 实测**并段是对的**
（普通段 4→3、自动编号列表 4→3 且重新编号正确、被删段后跟空间隔段 4→2）。
它的问题不在并段，在毁版式。这类结论跟版本绑死，换机器要重新量。

## 实测：多轮会签会套起来

第二个人改第一个人插入的字，结构就是 `w:ins > w:del`。处理留痕时如果按
「取一份子元素快照再平铺遍历」写：

```python
for node in list(root.iter()):          # 错
    for child in list(node):
        if child.tag == keep: 拆外壳
```

外层 `w:ins` 拆开后，里层 `w:del` 落到**已经遍历过的位置**上，再也不会被处理。
实测结果是接受修订后本该消失的字重新出现在正文里：

```
两轮送审稿  各单位要提高认识，落实到人，确保巡检务求实效。
接受后      各单位要提高认识，落实到人压实责任，确保巡检务求实效不走过场。   ← 删掉的字复活
```

要**递归、且先处理里层**，见 `revise.py` 的 `strip_revisions()`。同理，
新插入的内容不能直接塞进 `w:ins` 容器里——`w:ins` 套 `w:ins` 不合法，
要把容器在锚点前切开，见 `insertion_point()`。

## 实测：还原格式修订会顺手抹掉 sectPr

拒绝 `w:pPrChange` 是「用记录里的旧属性还原」，写成「把现在的 `w:pPr` 清空，再从记录里
全填回去」会出事：`w:pPrChange` 里那份 `w:pPr` 在 schema 里是 `CT_PPrBase`，
**装不下 `w:rPr` 和 `w:sectPr`**——记录里本来就没有这两个，清空就等于删掉。

同一份稿，A 段的段落标记带 `w:rPr`（黑体）、B 段的 `w:pPr` 里带 `w:sectPr`（Word 就是这样
存分节属性的），两段都有 `w:pPrChange`，拒绝一次：

| | A 段 `w:jc` | A 段落标记 `w:rPr` | B 段 `w:sectPr` |
|--|-----------|------------------|----------------|
| 送审稿 | center | 黑体 | 在 |
| 清空重填 | left（还原对了） | **丢了** | **丢了** |
| 保留后追加 | left | 黑体 | 在 |

对齐是还原对了的，所以只看「拒绝生效没有」这一条查不出来。丢 `w:sectPr` 就是纸张、版心、
每面行数全回默认——和 pandoc 那条毛病一模一样，只不过换成自己犯。

所以 `resolve()` 先把 `w:rPr` / `w:sectPr` 摘出来，填完基础属性再按 schema 顺序
（基础属性…, `w:rPr`, `w:sectPr`）追加回去。

顺带记一条量法上的坑：核对时写 `(ppr.find(qn("w:jc")) or ET.Element("x")).get(...)`
量出来三行全是 `None`——`w:jc` 没有子元素，**元素本身为假**，`or` 永远走右边。
判元素在不在只能用 `is not None`，见 `docx-traps.md` 最后一条。

## 实测：新增段抄哪一段的格式

新插入的段落和 run 必须抄现成段落的 `w:pPr` / `w:rPr`，两处都不能省：

- 不抄 `w:pPr`：丢左空二字、丢固定行距，段落跑回 `Normal` 样式。
- 不抄 `w:rPr`：丢 run 上的 `w:spacing w:val="-5"`，**那一行只排 27 字**（见
  `gongwen-format.md`「两个错得最多的参数」）。

抄谁也有讲究。无脑抄定位段会踩两次：

| 插在哪 | 无脑抄定位段的结果 | 应该抄 |
|--------|------------------|--------|
| 「一、巡检范围」后面插正文 | 3 号**黑体**的正文段 | 往后找最近的正文段 |
| 「二、时间安排」前面插「四、其他事项」 | 3 号**仿宋**的一级标题 | 同层的现成标题 |

所以 `template_para()` 的规则是：新段本身是层次序数就抄**同层**的现成标题，
否则定位段是正文就抄它、是标题或空段就往插入那一侧找最近的正文段。抄同层标题
还有个好处——拿到的是本文档实际在用的字体，生成时用 `--font-*` 换过字体的也跟着对，
不用在脚本里写死「黑体」。

这两种错 `--mode gongwen` 的层次字体检查能查出第二种，查不出第一种（正文没有
「必须是仿宋」的强制判定）。所以插完自己看一眼 `revise.py` 打印的「格式抄自 …」。
